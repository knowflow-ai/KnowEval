# KnowEval 评测规范 v0.1

本文说明 KnowEval 怎么判分、报告里的指标怎么算，以及测试集的文件格式。评测台和命令行用的是同一套规则。

## 1. 目标

KnowEval 评测中文企业文档上的 RAG 系统，回答选型和调优时最实际的三个问题：

1. 拿我们这类文档，谁**答得准**
2. 答不了的时候，谁会**坦白说不知道**，谁会**编一个答案**
3. 给出的引用，**点开能不能对上**

设计原则：

- **从原始文件出发**。测试集附带原始文档（PDF、Word、PPT、Excel、Markdown 等），被测系统自己解析、分块、检索、回答，整条链路一起考
- **闭卷能答的题不算 RAG 题**。模型出的题会做闭卷过滤：不查资料就能答对的题自动打回（无答案题除外）
- **判分可追溯**。判分交给裁判模型，提示词固定，裁判模型和版本写进结果文件
- **噪声要量出来**。建议每项跑两遍，报告给出置信区间和噪声底线

## 2. 被测系统

被测系统通过适配器接入，适配器只做两件事：

```
ingest(files) -> kb_handle        # 把原始文件交给被测系统建库，等解析完成
ask(kb_handle, question) -> Answer

Answer = {
  "text": str,                                  # 回答原文
  "citations": [{"doc": str, "page": int | None, "text": str}],
  "contexts": [str] | None,                     # 可选：检索到的上下文，用于错题归因
  "latency_ms": int
}
```

内置 KnowFlow、RAGFlow 两个适配器，自研系统用通用 HTTP 适配器（接口模板）接入。评测有两种方式：

- **测已有助手**（KnowFlow / RAGFlow）：直接问系统里配好的助手，不建库；可以对同一个助手做参数对照（临时建一个只改几项参数的助手，问完删除）。开跑时把助手当时的配置记进结果
- **完整测试**：按建库配置新建知识库和助手，上传测试集的文档；或者直接问自研系统的问答接口（文档需要预先导入，结果标 `manual_ingest`）

## 3. 题型

| 代码 | 题型 | 说明 |
|---|---|---|
| `F` | 单跳事实 | 答案在一处原文 |
| `M` | 跨文档多跳 | 需要串起两份及以上文档 |
| `T` | 表格数值 | 答案在表格里 |
| `C` | 计算与统计 | 需要对原文数字做运算或计数 |
| `X` | 比较 | 比较两个及以上对象 |
| `D` | 时间推理 | 涉及先后、区间、日期推算 |
| `V` | 图表与图片 | 答案在图表或图片里 |
| `L` | 长文档定位 | 答案藏在长文档深处的小节 |
| `K` | 信息冲突 | 不同文档或版本说法不一 |
| `N` | 无答案 | 文档里没有答案，应当说不知道 |
| `I` | 图文答案 | 回答必须带出文档里的某张图 |
| `G` | 全局关系 | 在整个知识库里汇总一组实体或计数 |

`M` 是沿一条链往下走，答案是一个点；`G` 是在全库里收集一整组，漏一个、多一个都不对。

## 4. 测试集格式

一个测试集（数据集）是一个目录：

```
manifest.json      # 名称、版本、许可、金丝雀字符串、文档清单（文件名、SHA-256、格式、来源地址）
questions.jsonl    # 每行一道题
docs/              # 原始文档
```

评测台里出的测试集在开始评测时会快照成这个格式，存在评测目录里，之后再改题不影响那次评测。

每道题一行 JSON：

```json
{
  "id": "manual-0042",
  "domain": "manual",
  "qtype": ["T"],
  "question": "XX 型路由器在 5GHz 频段下的最大发射功率是多少？",
  "answer": "23 dBm",
  "evidence": [
    {"doc": "router-xx-manual.pdf", "page": 37, "modality": "table", "quote": "5GHz 最大发射功率 23 dBm"}
  ],
  "hops": 1
}
```

必填与校验：

- `id`、`domain`、`qtype`、`question`、`answer` 必填；`qtype` 只能用第 3 节的代码
- `N` 类题的 `answer` 为空串、`evidence` 为空数组
- `evidence[].quote` 必须在对应文档里**逐字存在**（忽略空白差异），出题和导入时自动核对，对不上的去掉证据并说明
- 图表、图片形态的证据（`modality` 为 `chart`、`image`、`icon`）没有可逐字核对的原文，`quote` 写图中承载答案的内容

可选字段（只是交给裁判模型的提示，不按规则比对）：

- `answer_type`：`text`、`number`、`date`、`list`、`bool`，默认 `text`
- `unit`、`tolerance`：单位和允许误差，也可以直接把单位写在 `answer` 里
- `answer_aliases`：也算对的说法；`answer_distractors`：答成这些算错（如冲突题里的旧值）

可选字段（数据集的设计标注，用于分析，不影响判分）：

- `answer_images`：`I` 类题期望带出的图，`{"doc", "page", "bbox", "phash", "caption"}`
- `stage`（主考环节）、`traps`（干扰类型）、`n_kind`（无答案题的细分）、`hop_kind`（多跳方式），取值见[数据集设计](dataset-design-v0.1.md)
- `origin`：题目来源，`imported`（导入）、`generated`（模型出题）、`manual`（手动加题），报告按来源分开统计

### 4.1 文档与证据特征

题型说的是「问什么」，这里说的是「答案藏在什么样的文档、什么样的版面里」，两者正交，报告分别统计（按文档格式、按证据形态、跨页与不跨页、按跳数）：

- 清单里每份文档的 `format`（`pdf`、`scanned_pdf`、`docx`、`pptx`、`xlsx`、`html`、`md`、`image`）与 `features`（图文混排、多栏、图标、统计图表、手写、旋转）
- 每条证据的 `modality`（`text`、`table`、`chart`、`image`、`icon`、`formula`）与 `page_end`（跨页时的结束页）

导入题目时可以用更简单的 CSV：题目、答案必填，文档、原文可选（模板在评测台里下载）。

## 5. 判分：三档结果

| 结果 | 含义 |
|---|---|
| `CORRECT` 答对 | 回答的结论与标准答案一致 |
| `ABSTAIN` 坦白不知道 | 明确表示资料里找不到、无法回答 |
| `WRONG` 自信答错 | 给出了结论但结论错了，或者对无答案题编了答案 |

判定方式：

1. 接口出错记为 `ERROR`，回答为空记为 `ABSTAIN`，这两种不经过裁判模型
2. 其余回答全部交给裁判模型，一次给出 `CORRECT`、`WRONG`、`ABSTAIN` 之一。不用规则比对：数值的单位、量级、写法（「358.6 亿元」与「35860000000 元」）、日期写法、同义说法千变万化，规则判不准
   - 交给裁判的标准答案包括答案本身，以及第 4 节的提示字段（单位、误差、也算对、算错）
   - 裁判只拿到问题、标准答案和被测回答，看不到参考文档；被测回答放在定界符里，其中的文字不当指令
3. `N` 类题判为 `ABSTAIN` 记为对，给出任何结论都记为 `WRONG`
4. 判分结果可以人工改判；报告同时给出改判前、改判后的结果和人机一致率

错题归因：系统返回了检索上下文时，答错或说不知道的题会标出原因，「检索没找到」（标准证据不在上下文里）或「找到了没答对」。

## 6. 指标

| 指标 | 计算 | 说明 |
|---|---|---|
| **准确率** | `CORRECT` / 有答案的题（出错的题也在分母里） | 核心指标 |
| **自信错答率** | `WRONG` / （`CORRECT` + `WRONG`），含无答案题上编的答案 | 给了结论的题里错了多少，越低越好 |
| **拒答正确率** | `N` 类题中 `ABSTAIN` 的比例 | 不知道时会不会说不知道 |
| **过度拒答率** | 有答案的题中 `ABSTAIN` 的比例 | 能答的却说不知道 |

四个指标分开给，不合成一个总分；比例都带 95% 置信区间（Wilson 区间），并按题型、题目来源分组统计。

### 引用核对

对答对的题，检查引用能不能支撑答案：引用的文档与某条 `evidence` 一致，且引用文本与 `quote` 的字符重合率达到 0.6，判为「对得上」。

- **引用可核对率**：答对的题中，至少有一条引用对得上的比例
- **引用精确率**：所有引用中对得上的比例
- 系统不返回引用的，这两项记为不支持，不计零分

### 图文答案（`I` 类题）

文字结论照第 5 节判三档；另外核对回答里带出的图：下载后算感知哈希（64 位 dHash），与 `answer_images` 的汉明距离不超过 10 判为带对。

- **图片命中率**：`I` 类题中，期望的图全部带出的比例
- **图片误配率**：带出的图里，与题目无关的比例

## 7. 出题与校验

评测台新建测试集时，题目可以导入、让模型出，或者两种都要：

```
原始文档 → 参考解析（PDF 用 PyMuPDF，Office 用 MarkItDown，不用被测系统自己的解析器）
  → 导入的题：核对原文
  → 模型出题：按题型配比出题，每题逐字摘一句原文作证据
  → 自动校验：引文逐字核对、闭卷过滤（不看文档能答对的打回）、开卷复答、无答案题查证
  → 去重：和已有题重复的打回，导入和手动加的题优先保留
  → 页面上逐题浏览、修改、删除、恢复，或手动加题
```

## 8. 运行协议

1. 每个参评项的配置（建库参数、助手参数，或已有助手当时的配置快照）写进结果文件
2. 建议每项跑两遍；两遍结论不同的题数作为噪声底线写进报告，两次结果的差异在噪声范围内时会明确说明
3. 记录每题耗时
4. 数据集内容哈希、裁判模型、提示词版本、代码版本写进结果文件，任何结果都能追溯
5. 数据集文件内嵌金丝雀字符串，便于发现数据被混入模型训练语料

## 9. 许可

- **代码**：Apache-2.0
- **自带数据集**：见各自的 `manifest.json`。虚构文档和题目用 Apache-2.0；版权不允许分发的文档（如上市公司年报）只给下载清单（来源地址 + SHA-256）和下载脚本

## 附录：与现有评测的区别

| | RAGAS / DeepEval 等框架 | CRUD-RAG / RGB 等中文数据集 | KnowEval |
|---|---|---|---|
| 自带数据 | 否 | 是 | 是，也能用自己的文档出题 |
| 原始文件（PDF、Office、表格） | 不涉及 | 否，纯文本段落 | 是 |
| 区分「不知道」与「答错」 | 否 | 部分 | 是，三档判分 |
| 引用核对 | 否 | 否 | 是 |
| 图文答案 | 否 | 否 | 是，感知哈希核对回答里的图 |
| 防闭卷作答 | 否 | 否 | 是，闭卷过滤 + 虚构文档 |
| 噪声与置信区间 | 否 | 否 | 是 |
